# Tower of Food — Architecture Contract (v2)

This is the binding contract between every file in the game. If a name, attribute,
tag or remote appears here, every file must use it **exactly** as written.

The game is a food-themed **Tower of Hell** clone. The whole game is one giant
round tower: the lobby is the ground floor of the tower, and the obby sections
are stacked inside the shaft above it. A new random tower is built every 6–8
minutes; there are no checkpoints.

## 1. Files (and where they go in Roblox Studio)

| Repo file | Studio location | Class | Name |
|---|---|---|---|
| `src/ServerScriptService/TowerGame.server.lua` | ServerScriptService | Script | `TowerGame` |
| `src/ServerScriptService/TowerSections.lua` | ServerScriptService | ModuleScript | `TowerSections` |
| `src/StarterPlayer/StarterPlayerScripts/TowerHUD.client.lua` | StarterPlayer > StarterPlayerScripts | LocalScript | `TowerHUD` |
| `src/StarterPlayer/StarterPlayerScripts/TowerObstacles.client.lua` | StarterPlayer > StarterPlayerScripts | LocalScript | `TowerObstacles` |

* `TowerGame` requires the module with `require(script.Parent:WaitForChild("TowerSections"))`.
* The place starts as an **empty Baseplate template**. Everything is generated by
  code at runtime. `TowerGame` deletes the template `Baseplate` part and any
  `SpawnLocation`s on start, and builds its own lobby.
* No other assets are required. Do **not** reference any `rbxassetid://` that is
  not listed in this document (unknown IDs may be private or deleted). Built-in
  `rbxasset://` sounds are allowed: `rbxasset://sounds/electronicpingshort.wav`,
  `rbxasset://sounds/swoosh.wav`, `rbxasset://sounds/button.wav`.
* The only known-good custom asset: `rbxassetid://136713011360148` (the user's
  "Nugget" image, used for the Nugget Trail particle texture).
* Scripts are written in Luau, non-strict mode (no `--!strict` header), and must
  pass `luau-lsp analyze` with the Roblox definitions without errors (run
  `tools/check.sh`). Style: tabs, `local function`, `game:GetService(...)`.

## 2. World layout (studs; Y up; tower axis is the world Y axis through X=0,Z=0)

```
y = TopY+20 ┐  shaft walls end
            │  FINISH (disc floor r=24 at TopY, golden WinPad r=4, arch)
y = TopY    ┤
            │  section 8 … section 1   (each section: Height 24..44)
y = 12      ┤  TOWER FLOOR (top of pedestal) = BaseY of section 1
            │  LOBBY (ground floor) – walls r=54, ceiling ring at y=34..36
y = 0       ┘  lobby floor top
```

Constants (defined in `TowerSections.Constants`, the server reads them from there):

| Name | Value | Meaning |
|---|---|---|
| `SHAFT_RADIUS` | 26 | inner face of the tower shaft wall |
| `USABLE_RADIUS` | 24 | every part a section builds must stay inside this radius |
| `PLATE_RADIUS` | 6 | section entry/exit plates are discs of diameter 12 |
| `KEEP_OUT_RADIUS` | 7.5 | see section rules (§5) |
| `TOWER_FLOOR_Y` | 12 | top of the tower floor / BaseY of section 1 |
| `LOBBY_RADIUS` | 52 | inner face of lobby outer wall |
| `LOBBY_CEILING_Y` | 34 | underside of lobby ceiling ring |

**Lobby** (built once by `TowerGame`, folder `workspace.TowerOfFoodWorld`):
* Floor: disc r=56, top at y=0, white/cream SmoothPlastic, with neon ring inlays and
  two "soda pools" (blue glass, decorative, CanCollide floor under them).
* Outer wall ring r=52..54, height 0..36, made of ~40 segments, cream white with a
  neon strip.
* Ceiling ring between r=28 and r=54 at y=34..36 (segments).
* Pedestal: cylinder r=28 from y=0 to y=12 (top = tower floor, full disc so falling
  players land here).
* 4 staircases (at 0°, 90°, 180°, 270°) from the lobby floor (r≈46) up to the
  pedestal top edge (r=28): 12 steps, each 1 stud rise, 1.5 stud run, 12 wide.
* Shaft wall has a 12-wide × 14-tall doorway above each staircase (y 12..26).
* 4 `SpawnLocation`s on the lobby floor at r=40 between the staircases (45°,
  135°, …), Neutral, Duration 0, facing the tower.
* Decor: 8 braziers (with `Fire` + `PointLight`) beside the staircases, hanging
  banners on the lobby wall alternating ketchup red / mustard yellow / lettuce
  green, a "TOWER OF FOOD" sign above each doorway (SurfaceGui), a
  **Top Wins** board and a **How to play** board on the lobby wall.

**Tower shaft** (rebuilt each round, folder `workspace.Tower`):
* Wall ring of 32 segments per section band at r=26..28, tinted with that
  section's `Colors.Main` (Transparency 0.15, SmoothPlastic). Lobby band
  (y 12..34) is cream white. Finish band is gold-ish.
* For every section k>1: an entry **plate** (disc d=12, thickness 1, top at the
  section's BaseY, white with a coloured rim ring) — created by `TowerGame`, NOT
  by the section. Section 1 has no plate (the tower floor is its entry).
* A sign on the shaft wall inside each section near its BaseY+8: section name
  (big) and `by <Creator>` (small), SurfaceGui facing the axis.
* Finish: disc floor r=24 at TopY (top surface), a golden neon **WinPad** disc
  (d=8) in the middle, a glowing arch/portal. Touching WinPad = win.

## 3. Sections module (`TowerSections`)

```lua
local TowerSections = require(...)
TowerSections.Constants      -- table from §2
TowerSections.List           -- { SectionDef }
TowerSections.Build(def, params) -> (Model, Ctx)
--   params = { Parent: Instance, BaseY: number, Rotation: number (radians),
--              Seed: number }
--   Creates Model "Section_<Name>" under params.Parent and runs def.Build(ctx).
--   Errors propagate (TowerGame wraps the call in pcall).
```

`SectionDef`:
```lua
{
	Name = "Nugget Steps",        -- unique, shown on the wall
	Creator = "Chef Nugget",      -- shown as "by Chef Nugget"
	Difficulty = 1,               -- 1 easy, 2 medium, 3 hard
	Height = 30,                  -- even number 24..44
	Colors = { Main = Color3, Accent = Color3 },
	Build = function(ctx) ... end,
}
```

### 3.1 Local coordinates
Each section is built in **local coordinates**: the origin is the top-centre of
the entry plate. +Y is up. The exit plate (next section's entry) is the disc of
radius 6 occupying local y ∈ [Height-1, Height] centred on the axis. The
framework randomly rotates every section around the axis, so never assume a
world direction.

### 3.2 Ctx API (implemented in the module header — use ONLY these)
All positions/vectors passed to ctx are **local**. `opts` is an optional table
with any of: `Yaw`, `Pitch`, `Roll` (degrees), `Color`, `Material`, `Name`,
`Transparency`, `CanCollide`, `Parent` (a Model from `ctx:Group`),
`Thickness` (Platform/Disc only), `Reflectance`.
Default Material is SmoothPlastic, default Color is `ctx.Theme.Main`.

| Method | Result |
|---|---|
| `ctx.Height`, `ctx.Theme` | `Theme = {Main, Accent, Dark, Light, Danger}` (Color3) |
| `ctx.Rng` | a `Random` seeded per build |
| `ctx:CF(x,y,z, yaw?)` | world CFrame for a local point (+ yaw degrees) |
| `ctx:Pos(x,y,z)` | world Vector3 |
| `ctx:Polar(radius, angleDeg)` | returns `x, z` with x = r·cos θ, z = r·sin θ |
| `ctx:Block(x,y,z, sx,sy,sz, opts?)` | Part **centred** at local point |
| `ctx:Platform(x,y,z, sx,sz, opts?)` | Part whose **top** is at local y (thickness `opts.Thickness` or 1) |
| `ctx:Disc(x,y,z, diameter, opts?)` | flat cylinder whose **top** is at y |
| `ctx:Ball(x,y,z, diameter, opts?)` | sphere centred at point |
| `ctx:Cylinder(x,y,z, length, diameter, opts?)` | cylinder centred at point, axis along local X before Yaw/Pitch/Roll |
| `ctx:Beam(a: Vector3, b: Vector3, width, thickness, opts?)` | block from a to b (centre line). `opts.Round=true` → cylinder of diameter `width` |
| `ctx:Wedge(x,y,z, sx,sy,sz, opts?)` | WedgePart centred at point |
| `ctx:Truss(x,y,z, height, opts?)` | TrussPart 2×height×2 with **bottom** at y (height rounded up to a multiple of 2) |
| `ctx:Group(name, x,y,z)` | Model under the section whose pivot is that local point; pass it as `opts.Parent` to put parts in it |
| `ctx:Kill(target, keepLook?)` | tag `Kill` (touch = death). Unless keepLook, sets Neon + `Theme.Danger` |
| `ctx:Spin(target, degPerSec, axis?: Vector3)` | client-animated rotation about the target's pivot, around local axis (default up) |
| `ctx:Move(target, offset: Vector3, period, phase?)` | client-animated back-and-forth between pivot and pivot+offset |
| `ctx:Swing(target, pivot: Vector3, axis: Vector3, amplitudeDeg, period, phase?)` | pendulum rotation around a local pivot point |
| `ctx:Cycle(part, mode, onTime, offTime, phase?)` | mode `"Hazard"` (deadly while on) or `"Vanish"` (solid while on, gone while off) |
| `ctx:Melt(part, delay?, respawn?)` | vanishes `delay` s (default 0.5) after the local player touches it, back after `respawn` s (default 3) |
| `ctx:Bounce(part, power?)` | trampoline; launches the player upward at `power` studs/s (default 80 ≈ 16 studs high) |
| `ctx:Conveyor(part, velocity: Vector3)` | moves players standing on it (local velocity, studs/s) |
| `ctx:Slippery(part)` | zero friction |
| `ctx:Random(min,max)`, `ctx:RandomInt(min,max)`, `ctx:Chance(p)` | helpers on `ctx.Rng` |

`target` may be a BasePart or a Model from `ctx:Group`. Animated groups must not
be nested inside other animated groups. Animated parts that players can stand
on carry the player (client-side).

## 4. Movement physics (default character — design for these)

* WalkSpeed 16, JumpHeight 7.2, Gravity 196.2. Max flat jump ≈ 10 studs edge-to-edge.
* **Comfortable** rules (difficulty 1–2): rise ≤ 4 per jump, flat gaps ≤ 6,
  gaps ≤ 4 when rising 3+, platforms ≥ 3×3.
* **Hard** (difficulty 3): rise ≤ 5.5, flat gaps ≤ 8, platforms ≥ 2×2,
  beams ≥ 1 wide.
* Truss ladders let players climb any height. Bounce pads give extra height.
* Skills / coils / mutators can make players faster or jump higher — never
  design something that *requires* them.

## 5. Section rules (the test harness enforces these)

1. Every part stays within horizontal radius `USABLE_RADIUS` (24) of the axis,
   including moving parts at every point of their motion.
2. Every part stays within local y ∈ [0, Height].
3. **Keep-out zones** (nothing collidable, nothing deadly): horizontal radius
   < 7.5 for local y ∈ [0, 6] (launch space above the entry plate) and for local
   y ∈ [Height-7, Height] (space around/below the exit plate).
4. A beatable path exists from the entry plate (top y=0, r=6) to the exit plate
   (top y=Height). The final jump onto the exit plate is from a safe standing
   surface whose top is in [Height-4.5, Height-1.5] and whose nearest edge is
   at radius 7.5..10.5.
5. All parts Anchored (the module does this). Nothing relies on server physics.
6. Kill parts must look deadly (the default Kill look). Every section should
   be fun and look like its food: use several colours/parts per object.
7. Aim for 25–70 parts per section (performance), max 120.

## 7. Player attributes (server sets, clients read)

`Coins` (number), `Level`, `LevelXP`, `LevelNeed`, `SkillPoints` (unspent),
`Wins`, `Skill_<Id>` (int), `Owned_<ItemId>` (bool), `EquippedTrail` (string,
"" = none), `Pass_<Key>` (bool), `SkipUsed` (bool, this round), `Stage`
(sections cleared this round, 0..8).

Leaderboard (`leaderstats`): `Level` (IntValue), `Wins` (IntValue).

## 8. Gameplay rules (server)

* Coins: 12.5 per section cleared + 100 top bonus (200 per full climb).
  Multipliers stack: x2 Coins pass ×2, VIP ×1.25, `Coins` skill +5%/point,
  `x2` mutator ×2.
* XP: 10 per section, 100 per win; `XP` skill +5%/point. Level n→n+1 needs
  `100 + (n-1)*50` XP. One skill point per level gained.
* Skills (max 10 each): `Speed` (+0.4 WalkSpeed/pt), `Jump` (+0.3 JumpHeight/pt),
  `Coins` (+5% coins/pt), `XP` (+5% XP/pt).
* A section is "cleared" when the player is standing (FloorMaterial ≠ Air) inside
  the shaft with feet at or above the next section's BaseY - 1. The final section
  is paid by the WinPad together with the top bonus. Each section pays once per
  round.
* Win: touch WinPad → coins/XP, Wins+1, Notify all, teleport back to the lobby
  after 3 s. Once per round.
* Round: 6–8 minutes (random). On reset: new tower, all players respawned in
  the lobby, 40% chance of a random mutator for the round.
* Shop (coins, owned forever): Gear `SpeedCoil` 250 (WalkSpeed +10 while held),
  `GravityCoil` 400 (cancels 55% gravity while held), `FusionCoil` 1000 (both).
  Trails: `KetchupTrail` 150, `MustardTrail` 150, `RainbowTrail` 500,
  `SprinkleTrail` 800 (particles), `GoldenFryTrail` 1500. One trail equipped.
* Passes (`CONFIG.PASSES`, IDs start at 0): `X2Coins`, `DoubleJump`,
  `SkipSection`, `VIP` (+25% coins, gold "VIP" overhead tag), `NuggetTrail`
  (nugget particles, texture `rbxassetid://136713011360148`).
* Codes (Menu > Codes): `FOOD` = 100 coins, `NUGGET` = 50 coins, once each.
* DataStore `TowerOfFood_v1`, key `Player_<UserId>`, value
  `{Coins, XP, Wins, Owned = {[id]=true}, EquippedTrail, Skills = {[id]=n},
  Codes = {[code]=true}}` (missing fields default; v1 saves are compatible).
  OrderedDataStore `TowerOfFood_Wins` (key = UserId string, value = Wins) feeds
  the lobby Top Wins board.

## 9. Client animation contract (tags + attributes written by the module)

All animation is client-side and time-synced with `workspace:GetServerTimeNow()`
so every player sees the same thing. Tagged instances live under
`workspace.Tower`. The client stores each target's **base pivot** (for a Model
`GetPivot()`, for a part its `CFrame`) the first time it sees it.

| Tag | On | Attributes |
|---|---|---|
| `Kill` | BasePart | — touching kills the local player |
| `Spin` | BasePart/Model | `SpinSpeed` (deg/s), `SpinAxis` (Vector3 world unit). pivot = base rotated about base position by `SpinSpeed*t` around `SpinAxis` |
| `Move` | BasePart/Model | `MoveOffset` (Vector3 world), `MovePeriod` (s), `MovePhase` (0..1). pos = base + offset·(0.5 − 0.5·cos(2π(t/period+phase))) |
| `Swing` | BasePart/Model | `SwingPivot` (Vector3 world point), `SwingAxis` (Vector3 world unit), `SwingAngle` (deg), `SwingPeriod`, `SwingPhase`. angle = SwingAngle·sin(2π(t/period+phase)) |
| `Cycle` | BasePart | `CycleMode` ("Hazard"/"Vanish"), `CycleOn`, `CycleOff` (s), `CyclePhase` (0..1), `BaseColor` (Color3). Cycle position c = (t/(on+off) + phase) mod 1; "on" while c·(on+off) < on. Warn during the last 0.6 s before switching. Hazard on = Neon + Danger red and deadly; off = BaseColor, safe. Vanish off = Transparency 1 & CanCollide false |
| `Melt` | BasePart | `MeltDelay`, `MeltRespawn` |
| `Bounce` | BasePart | `BouncePower` |
| `Conveyor` | BasePart | `ConveyorVelocity` (Vector3 world). Client sets `AssemblyLinearVelocity` |

Danger red is `Color3.fromRGB(255, 45, 45)`.
